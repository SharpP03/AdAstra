# PLAYTESTS – NOTATKI I POMIARY

Surowe notatki z playtestów: jeden plik na playtest, `<RRRR-MM-DD>-<krótka-nazwa>.md` (np. `2026-10-28-vertical-slice.md`). Pliki są materiałem źródłowym do pracy inżynierskiej (rozdział o testach) i wejściem dla poprawek po playteście. Wnioski, które zmieniają projekt, trafiają do `Assets/DOCS/GAMEPLAY.md`, a decyzje z nich wynikające – do `../design_decisions.md`.

Szablon:

```markdown
# <nazwa playtestu>, <branch / commit>, <RRRR-MM-DD>

**Cel:** <co sprawdzamy; pytania z taska, np. #76>
**Build / konfiguracja:** <commit, istotne wartości SO, jeśli zmienione>

## Runy
| # | Wynik | Czas runu | Rdzenie zebrane / spalone / dowiezione | Zapas do fali przy bramie | Najmniejszy dystans do fali | Uwagi |
|---|-------|-----------|----------------------------------------|---------------------------|-----------------------------|-------|

## Obserwacje
* <co się działo, gdzie było nudno / za trudno / niejasno – fakty, bez rozwiązań>

## Odpowiedzi na pytania playtestu
* <pytanie> – <odpowiedź>

## Wnioski i następne kroki
* <wniosek> → <zmiana lub task>

## Materiały
* <zrzuty ekranu, nagrania – ścieżki lub linki>
```
